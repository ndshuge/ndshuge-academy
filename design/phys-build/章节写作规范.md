# 物理学院章节写作规范（批量生产用）

> 每个章节数据文件必须严格按此规范产出。参考样板：`content/phys-ch01.js`（已定稿）。

## 一、文件命名与骨架

- 路径：`E:\Hanako\学习计划\四学院\design\phys-build\content\phys-ch{NN}.js`（NN 为两位章号，如 `phys-ch04.js`）
- 文件顶部写注释块：章号、章名、对应教材节号、题型说明
- 变量名：`var CH{NN} = { ... };`（如 `var CH4 = {...}`），**变量名不带前导零**
- 文件末尾必须是 `};`

## 三、题目结构

```js
{ "type": "choice", "q": "题干", "options": ["A", "B", "C", "D"], "answer": 0, "explain": "解析" }
```

- `answer` 是**正确选项的下标**（0~3），不是字母
- 每题必须 4 个选项（不多不少），且**正确答案的下标要打散**：20 题里四个下标（0/1/2/3）各出现 4~7 次，任何位置不得低于 3 次或高于 8 次。写完必须统计一遍
- **打散 ≠ 循环**：严禁把 answer 写成 0,1,2,3,0,1,2,3… 这种可预测的周期序列（学生三题就能摸出规律）。四个值要交错无序，自检时看一眼序列本身
- `explain` 必须说明「为什么对」并顺带点破干扰项的错因，60~160 字
- **`explain` 里禁止用「选项 A」「故 D 正确」这类字母指代**（选项换位或校对后会错位，读者也会困惑）。要指出某个选项时，直接描述它的内容，例如「把单位混淆的那一项」「认为匀速时加速度仍为 g 的说法」

## 四、命题规范（硬约束）

**分布要求**（每章 20 题合计）：
- 记忆锚点题 ≤ 30%（≤6 题）：考定义、公式、常数的复述
- 机制判别题 ≥ 40%（≥8 题）：给**新情境**，考同一规律能否迁移
- 因果/反事实/评价题 ≥ 30%（≥6 题）：问「为什么」「如果……会怎样」「哪种说法更准确」

**内容要求**：
- 题干必须给**具体的、可算可推的情境**，禁止「谁发现了什么定律」这类人名题
- quiz 与 exam 的题目**严禁重复**（知识点可重叠，题目不能像）
- 数值题的答案要真的算对，**必须自己验算一遍**
- 每个干扰项都要有「像那么回事」的错因（常见误解），不要凑数

## 五、格式红线（违反会导致渲染出错）

1. **禁止 markdown 加粗** `**文字**` —— 引擎不认，会渲染成 `^文字·` 乱码
2. **禁止英文双引号出现在字符串内部** —— 会截断 JS 字符串。引用一律用中文直角引号「」
3. **禁止裸露的星号 `*`** —— 引擎的公式渲染会把 `*` 转成 `·`
4. 公式用纯文本形式写：`v = dr/dt`、`a_n = v²/ρ`、`F = GMm/r²`（可用 ² ³ √ π Δ Σ ω 等符号）
5. JSON 字符串内不能有未转义的换行

## 七、风格基调

- 讲义要**从底层原理讲起**，不堆结论。用类比和具体例子落地抽象概念
- 解析要像老师在你耳边讲，不是念标准答案
- 避免「不是……而是……」句式，少用破折号
- 立场：讲清物理图像，而不是背公式
